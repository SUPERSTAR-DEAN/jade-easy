# Jade : 课程表管理
*(asa benchmark)*

使用智能体解决约束满足问题（CSP）的实验。

我们先从一个"简单"的课程表管理例子开始。

涉及角色：教师、学生分组、以及时间槽。

---
### 问题 A 的描述
从不同视角（教师、学生、教室管理员）看，问题可以这样定义：
- 三组学生（$g_1$、$g_2$、$g_3$）每组都要上两门两小时的课，分布在两天（$j_1$ 和 $j_2$），由一位老师（$e_1$、$e_2$ 或 $e_3$）教授。
- 三位老师（$e_1$、$e_2$、$e_3$）每人要教两门两小时的课，分布在两天（$j_1$ 和 $j_2$），面向三组学生（$g_1$、$g_2$、$g_3$）。
- 三间教室（$s_1$、$s_2$、$s_3$）每间都要接待两门两小时的课，分布在两天（$j_1$ 和 $j_2$），由一位老师（$e_1$、$e_2$ 或 $e_3$）授课。

**时间槽**：$j_1$ 和 $j_2$ 是工作周的两天，从 8 点到 18 点，中午 12-14 点有 2 小时休息。
为简化，时间槽限定为 8-10、10-12、14-16、16-18。

**约束**：
还有其他约束：
- 老师在某些时间槽有不可用：
  次级约束 (2) 在没有其他解时可以违反：
  - $e_1$ 不能授课：(1) $j_1$ 16-18 点；(2) $j_2$ 14-16 点。
  - $e_2$ 不能授课：(1) $j_2$ 10-12 点；(2) $j_1$ 16-18 点。
  - $e_3$ 不能授课：(1) $j_1$ 14-16 点；(2) $j_2$ 8-10 点。

- 三间教室 s1、s2、s3 都可用于这些课，但它们本身也有约束：
  - 教室 $s_1$ 在 $j_1$ 10-12 点不可用 (1)
  - 教室 $s_2$ 在 $j_2$ 16-18 点 (1) 和 8-10 点 (2) 不可用
  - 教室 $s_3$ 在 $j_2$ 16-18 点 (1) 和 $j_1$ 14-16 点 (2) 不可用
  - 只有教室 $s_1$ 和 $s_2$ 配有投影仪

- 课程本身也有设备约束；例如：
    - 每个组每门课都至少需要使用一次投影仪。

---

**问题的求解方法。**

可以有多种方法。
例如：
- 若 $p_1$ 和 $p_2$ 是与违反约束对应的权重（$p_1 + p_2 = 1$ 且 $p_1 > p_2$）
- 老师 $e_i$ 的满意度通过效用函数定义：
$u_{e_i}(agenda) = (p_1 \times ok_{contrainte_1} + p_2 \times ok_{contrainte_2})$，其中 $ok_{contrainte_i} =$ 0 或 1，表示约束 (i) 是否被满足。
- 注意，这只从 $e_i$ 的视角评分，不关注教室不可用性的约束。

对某个老师，可能存在多个最大化其效用函数的解。但该值可能很低。
也可能不存在任何解能同时最大化每个老师、教室、分组的效用函数。


## 智能体化
  - 通过定义 AEIO 角色（Actors, Environments, Interactions, Objects）来智能体化问题。
    - 可以为教师、分组、教室、时间槽、教师协调、教室协调等定义智能体。
  - 更具体地，定义智能体、它们的角色、行为、交互。
    - 你会用什么解决机制？（投票、谈判、适应、市场、……）

  - 说明用于实现你所描述角色的行为类型。只需给出它们的名称和类型（简单、循环、……），
    其功能用普通文字描述。
  - 给出 JADE 智能体之间为求解课程表问题而通信的对话框图，并指明涉及的行为。
